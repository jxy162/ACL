## 2. 关键模型（定义）

### 2.1 版本

```csharp
public sealed record VersionName(string Raw) : IComparable<VersionName>; // 封装版本名比较
public sealed record McVersionSpec(
    VersionName Vanilla, Version Comparable, int Drop,
    bool IsSnapshot, bool IsFool, DateTimeOffset ReleaseTime, bool Reliable);
public sealed record ComponentSet(
    IReadOnlyDictionary<ModLoaderKind, string> Loaders,
    OptiFineRef? OptiFine, string? FabricApiVersion, string? OptiFabricVersion, string? QuiltVersion);
```

- `Comparable`：可比较的三段式版本号（旧格式次版本上移）。
- `Drop`：可比较 Drop 序数（用于排序/筛选）。
- `Reliable`：版本号是否来自可靠依据（非猜测）。

## 3. 存储分层

| 层 | 载体 | 位置 |
| --- | --- | --- |
| 启动器配置 | JSON | `ACL/config.json`（应用数据目录） |
| 实例覆盖配置 | JSON | `ACL/instances/<id>.json` |
| 实例/安装清单 | JSON | 实例目录或应用数据目录（见 §5） |
| 缓存 | JSON/二进制 | `ACL/cache/` |
| 密钥/令牌 | 受保护存储 | 平台密钥链 / DPAPI / 环境变量 |
| 日志 | 文本（轮转） | `ACL/logs/` |

## 4. 配置服务

```csharp
public interface IConfigurationStore {
    T Get<T>(ConfigKey<T> key, ConfigScope scope = default);
    void Set<T>(ConfigKey<T> key, T value, ConfigScope scope = default);
    IDisposable Subscribe<T>(ConfigKey<T> key, Action<T> onChange);
    Task SaveAsync(CancellationToken ct = default);
}
public readonly record struct ConfigScope(string? InstanceId = null);
```

- 每个配置项声明：键、类型、默认值、是否加密、迁移规则。
- 分实例：`ConfigScope.InstanceId` 决定作用域，未设回落全局。
- 迁移：`SchemaVersion` + `IConfigMigrator`（幂等、可回滚、迁移前备份）。

## 5. 目录布局

```
<AppData>/ACL/                     启动器数据（与游戏目录分离）
├─ config.json                     主配置
├─ instances/<id>.json             实例级配置/清单（也可放实例目录）
├─ cache/
│  ├─ cache-version.json           缓存结构版本
│  ├─ version-manifest.json        版本清单
│  └─ versions/<id>.json           版本 JSON 缓存
├─ logs/Log-YYYYMMDD.txt           日志（轮转）
├─ temp/                           任务临时目录
└─ secrets/                        受保护存储（若平台无密钥链则加密文件）

<.minecraft>/                      游戏目录
├─ versions/<name>/<name>.json
├─ versions/<name>/<name>.jar
├─ libraries/  assets/{indexes,objects}
└─ mods/ resourcepacks/ shaderpacks/ saves/ config/
```

> 启动器数据目录可配置；默认位于用户应用数据区。游戏目录可多个（"版本隔离"）。

> **便携式布局（ADR-0012）**：默认把启动器数据与游戏目录都放在**启动器可执行文件所在目录**——数据即该目录，游戏目录为同目录下的 .minecraft/；可用环境变量 ACL_GAME_DIR 覆盖。便于整体拷贝与文件查找。

## 6. 缓存与失效

| 缓存 | 内容 | 失效 |
| --- | --- | --- |
| 版本清单 | 全量版本表 | TTL + 手动刷新 |
| 版本 JSON | 单版本详情 | TTL |
| 实例列表 | 目录内实例元数据 | `CacheVersion` 版本号 |
| 本地资源 | jar 内元数据 | `LocalResourceCacheVersion` |
| HTTP 响应 | 任意 URL | 新鲜度/条件请求 |

**规则**：缓存结构变更必须递增对应版本号常量。

## 7. 序列化约定

- 默认 `System.Text.Json`；读写外部格式（Mojang JSON、CurseForge/Modrinth 响应）可直接映射，必要时用 Newtonsoft 兼容。
- 可空字段忽略 null；时间统一 **UTC**；路径比较用 `OrdinalIgnoreCase`。
- 文本 UTF-8；读取外部文本按 BOM → 严格 UTF-8 → GB18030 回退。

## 8. 数据迁移（若需兼容既有启动器）

- 目标：能读 `PCL\` 与 `.minecraft` 常见布局，迁移到 ACL 结构。
- 原则：只读兼容 → 一次迁移 → 备份 + 幂等 + 可回滚。
- 迁移器接口：`IConfigMigrator`、`IInstanceMigrator`。
