# 00 · 项目愿景与产品定位

## 1. 一句话定位

**ACL** 是一个从零自研、内核与界面彻底解耦、可跨平台的 Minecraft（Java 版）启动器；它把"启动/下载/认证/资源管理"当作一组**可测试、可组合的服务**来构建，而不是一堆和界面纠缠的脚本。

## 2. 为什么自研（而非继续改 PCL）

| 维度 | PCL 派生（现状 APCL） | 自研 ACL（目标） |
| --- | --- | --- |
| 可维护性 | 核心逻辑与 WPF/全局状态强耦合 | 内核零 UI 依赖，可单测 |
| 可移植性 | 绑定 .NET Framework 4.8 + WPF（Windows） | .NET 10 跨平台，界面可替换 |
| 可扩展性 | Module + 全局变量，扩展靠改源码 | 接口/服务/依赖注入，可替换实现 |
| 正确性保障 | 依赖手工验证 | 单测 + 桩服务集成测试 |
| 许可 | 受上游许可约束（须满足署名/命名/开源要求） | 净室自研，许可自主 |
| 技术债务 | 继承上游历史包袱 | 现代工具链与架构 |

> 参考研究（**只学不改用**）见 [10-参考实现研究](10-参考实现研究-PCL与ACL架构剖析.md)。

## 3. 目标用户

- 主力：**中文 Minecraft 玩家**（正版/离线/第三方服），需要稳定、快速、可定制的启动体验。
- 次要：**整合包作者/服主**（批量安装、导出实例、崩溃诊断）。
- 远期：**跨平台玩家**（Windows / Linux / macOS）。

## 4. 核心能力（Scope）

### 必做（MVP）
- 版本管理：原版 / 快照 / Forge / NeoForge / Fabric / LiteLoader / OptiFine / Quilt。
- 版本下载与**文件补全/校验**（多源 + 镜像 + 断点续传）。
- Java 自动探测、选择与下载安装。
- 登录：**Microsoft 正版** / 离线 / 第三方（authlib-injector / Yggdrasil）。
- 启动：参数生成、natives 解压、进程启动与监控、崩溃归因。
- 实例（隔离）管理与配置。

### 重要
- 社区资源：CurseForge / Modrinth 检索与安装（Mod/资源包/光影/数据包/地图）。
- 整合包导入：CurseForge / Modrinth / HMCL / MMC / MCBBS / 通用压缩包。
- 崩溃诊断与日志导出。

### 可延后
- 联机、皮肤/披风、更新服务、遥测（默认关闭）、多语言、无障碍。

### 非目标（Non-goals）
- 不做"游戏内加速/作弊、外挂、盗版分发"。
- 不内置或捆绑 Minecraft 本体资源（仅按官方协议分发与下载）。
- 不追求与某启动器 100% 功能对齐；以**自家架构与体验**为准。

## 5. 设计原则（宪法）

1. **净室自研**：只依据公开规范与外部行为实现；不复制他方源码、不沿用其命名。
2. **内核零 UI 依赖**：所有交互经事件/进度/结果对象表达。
3. **显式上下文**：禁止全局可变状态；实例/游戏目录/登录态显式传递或注入。
4. **一切可注入**：文件系统、时钟、HTTP、进程、随机源可注入，便于测试。
5. **契约优先**：对外只暴露抽象层与 DTO；实现可迭代。
6. **小步交付**：每个服务可独立运行与测试。
7. **安全默认**：HTTPS 默认开启、密钥不落盘、日志脱敏。
8. **用户可控**：网络/镜像/遥测/外观均可配置。

## 6. 差异化亮点（相对既有启动器）

- **内核可测试**：具备真实单元测试与桩服务集成测试，而非纯手测。
- **跨平台前景**：内核与 UI 解耦，非 Windows 平台可用同一内核。
- **可脚本化**：`ACL.Cli` 让"安装/启动/导出"可被 CI 与自动化调用。
- **诊断优先**：结构化崩溃归因（错误码 + 规则库 + 可分享报告）。
- **现代 UI**：Avalonia + MVVM，支持主题/动效/手柄导航（后续）。

## 7. 成功标准（可度量）

| 维度 | 指标（示例）|
| --- | --- |
| 功能 | 能从零完成"下载原版 + 登录 + 启动"闭环；支持主流加载器组合 |
| 质量 | 内核单测覆盖主路径；崩溃归因对样例集命中率达标 |
| 性能 | 元数据请求有缓存；下载支持多源/多线程；冷启动可接受 |
| 稳定 | 网络失败可回退；进程异常可归因；无未捕获异常弹出 |
| 体验 | 界面响应流畅；关键操作有进度与取消 |
