# 13 · 功能设计与交互约定

> 本文记录 2026-10-22 这一轮功能改造的**用户可见行为**与**交互约定**，
> 以及它们与内核的对应关系。实现细节见 [02 内核架构](02-内核架构与模块划分.md) 与
> [12 界面设计语言](12-界面设计语言.md)。

## 1. 账号：离线与正版分区，多账号本地管理

| 约定 | 说明 |
| --- | --- |
| 分区展示 | 启动页左栏分"正版账号""离线账号"两块，互不混排。 |
| 正版登录 | 点击后自动唤起浏览器（`verification_uri_complete`）、弹出对话框并**自动复制设备码**；整个过程在后台线程执行，不阻塞界面。 |
| 离线登录 | 输入玩家名即创建账号，UUID 由 `OfflineIdentity` 确定性推导。 |
| 多账号 | 只管理**本机已登录过**的账号：点击即切换（置为最近使用），行内 ✕ 删除（同时删除其加密令牌）。 |
| 落盘 | 档案 `ACL.accounts.json`（明文元数据）+ `accounts/*.json`（令牌经 `ISecretProtector` 加密）。 |

## 2. 版本四分法

清单类型与版本名合成四个分区：**正式版**（`release`）、**快照版**（`snapshot`）、
**预览版**（快照中含 `pre`/`rc`）、**远古版**（`old_beta`/`old_alpha`）。

- 下载页与启动页都提供该分区筛选；
- 下载页加载**全部**版本（不再截断），并显示各分区计数；
- 资源页/启动页的"游戏版本"默认跟随当前选择。

## 3. 安装二级页面（加载器前置安装）

下载页任意版本 → 点击"安装"进入二级页面：

| 加载器 | 路径 | 是否需要 Java |
| --- | --- | --- |
| 原版 | 拉取版本 JSON → 写入本地实例 → 补齐客户端/库/资源索引 | 否 |
| Fabric / Quilt | 官方 install profile → 重写 `id` → 补齐依赖 | 否 |
| Forge / NeoForge | 官方安装器 `--installClient` 无交互执行 → 差集识别产出实例 | **是** |
| OptiFine | 补丁包按 Maven 布局落盘 → 生成继承实例（建议与 Forge 组合） | 否 |
| Iris | 先装 Fabric，再从 Modrinth 取 Iris 前置模组到 `mods/` | 否 |

页面提供：加载器与版本选择、实例名（自动推导）、Java 探测与指定、安装日志、进度与"启动已安装实例"。

## 4. 资源页：推荐资源与整合包直下

- **推荐资源**：一键加载热门整合包 / 模组 / 光影（按下载量），显示缩略图、作者与下载量。
- **整合包一键安装**：下载 `.mrpack` / `.zip` → `ModpackInstaller` 安装 → 按清单加载器要求
  补齐基础版本与加载器 → 刷新实例 → 自动跳转"游戏列表"。
- 拖入整合包文件到窗口同样会走导入流程。

## 5. 启动动画

启动时显示全屏覆盖层（自研 `BusyRing` 旋转环 + 阶段 / 登录方式 / 进度 / 下载速度 + 小提示），
进入与退出都走可打断的声明式过渡；"隐藏面板"不影响游戏进程，"取消启动"终止本次启动。

> 该覆盖层只参考了参考实现的**信息结构与动效方向**（进度 + 阶段 + 小提示 + 取消），
> 控件与动效均为本项目独立实现。

## 6. 没有"启动计划"

- 启动页：选择版本 → 已安装则直接"启动游戏"，未安装则"安装 / 加载器配置"。
- 游戏列表：**只列本机实例**，选中即可启动。
- 实例设置（二级页面）：内存上下限、Java 路径、附加 JVM / 游戏参数、工作目录、备注；
  持久化到 `ACL.config.json` 的 `Instances` 字典，留空即沿用全局设置。

## 7. 数据与目录

| 文件 | 内容 |
| --- | --- |
| `ACL.config.json` | 全局设置、游玩时长、`Instances` 实例设置、当前账号 ID |
| `ACL.accounts.json` | 本地账号档案（离线 / 正版） |
| `accounts/*.json` | 各账号的加密令牌 |
| `ACL.key` | 非 Windows 平台的 AES 回退密钥（Windows 用 DPAPI，不需要该文件） |
| `.minecraft/` | 与启动器同目录的游戏根目录（`ACL_GAME_DIR` 可覆盖） |
