## 4. 代码规范

### 4.1 C#

- 开启 `Nullable`；避免可空告警。
- 命名：类型/方法/属性 `PascalCase`，参数/局部 `camelCase`，私有字段 `_camelCase`（或遵循 `.editorconfig`）。
- 大括号不换行；`switch` 表达式优先。
- 异步方法以 `Async` 结尾；**禁止 `async void`**（事件处理器除外）。
- 只读优先：`record`、`readonly`、`init`。
- 公共 API 必须写 XML 注释。
- 一个文件一个主要类型（DTO 可聚合）。

### 4.2 分析与格式

- `.editorconfig` 统一风格；CI 跑 `dotnet format --verify-no-changes`。
- 启用分析器（`EnableNETAnalyzers`）；内核工程 `TreatWarningsAsErrors`。
- 禁止在代码里硬编码 URL/密钥/文案（用常量/资源/`ISecretProvider`）。

### 4.3 文本与编码

- UTF-8 无 BOM；换行 LF（`.gitattributes` 归一化）。

## 5. 提交规范（Conventional Commits）

```
<type>(<scope>): <中文描述>
```

- `type`：`feat` / `fix` / `refactor` / `perf` / `style` / `docs` / `test` / `build` / `ci` / `chore`。
- `scope` 建议：`core`、`download`、`mirror`、`version`、`java`、`auth`、`launch`、`resources`、`modpack`、`diag`、`config`、`ui`、`cli`。
- 破坏性变更用 `!` 或 `BREAKING CHANGE:` 脚注。

示例：

```
feat(download): 支持多源并发取先与断点续传
fix(auth): 处理微软令牌过期后的自动刷新
docs(core): 补充任务流水线进度树说明
```

## 6. 分支与版本

- `main` 为稳定分支；功能走 `feat/*`，修复走 `fix/*`。
- 版本：内核各工程独立 SemVer；应用版本单独。
- 发布：`chore(release): vX.Y.Z` 提交 + Git tag。
- 公共契约破坏性变更需 ADR（见 [11](11-决策记录与变更日志.md)）。

## 7. CI

```yaml
# .github/workflows/build.yml（拟定）
name: build
on: [push, pull_request]
jobs:
  build-test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [windows-latest, ubuntu-latest]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with: { dotnet-version: '10.0.x' }
      - run: dotnet restore
      - run: dotnet build ACL.sln -c Release --no-restore
      - run: dotnet test --no-build -c Release
      - run: dotnet format --verify-no-changes
```

- 密钥（Client ID/API Key）通过 CI secrets 注入，**不写入源码**。
- 产物上传 + 可选签名（Windows）。

## 8. 发布与分发

| 平台 | 形式 |
| --- | --- |
| Windows | `win-x64` 单文件/便携包；可选 MSIX |
| Linux | AppImage / tar.gz |
| macOS | .app / .dmg |

- 发布前：`dotnet test` 全绿、`dotnet format` 干净、更新变更日志。
- 自动更新走 `IUpdateService`（可延后）。

## 9. 依赖管理

- 使用 `Directory.Packages.props`（中央包版本管理，CPM）统一版本。
- 新增依赖需：评估许可、记录到 `THIRD-PARTY-NOTICES`、评估体积。
- 优先框架自带能力；避免为小功能引入大依赖。
